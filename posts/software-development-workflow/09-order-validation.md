### 一、评价你的访谈思路

正确

你这次使用的是一种很重要的需求调研方法：情境访谈（Contextual Inquiry）。

它的核心不是让用户描述自己理想中的系统，而是让用户展示真实工作过程。

为什么这种方法有效？

假设你直接问：

「订单导入需要什么功能？」

运营主管可能回答：

「需要 Excel 导入、自动匹配商品、自动创建订单。」

但这些回答并没有告诉我们：

- Excel 格式有哪些差异？
- 商品如何匹配？
- 匹配失败怎么办？
- 重复订单怎么识别？
- 创建失败后如何恢复？

而让用户演示最近一次操作，就更容易发现实际问题和隐藏规则。

**本轮评价：你的提问方向正确，能够从用户表达转向真实业务行为。**

### 三、确定订单创建规则

首先要区分两个概念：

- 订单导入：外部订单数据进入系统。
- 订单创建：系统将通过必要校验的数据形成正式订单记录。

不建议把 Excel 上传成功直接等同于订单创建成功。

#### 1. 推荐的订单创建流程

#### 订单创建业务流程 V0.2

**上传订单数据**

Excel / API / 手动录入

**解析原始订单**

保留来源、原始订单编号、原始商品信息

**数据校验**

格式、编号、商品、客户、金额

**商品匹配**

映射内部商品和 SKU

通过

**创建正式订单**

未通过

**进入异常队列**

这里有一个重要设计原则：

**原始订单数据和正式订单数据应该能够区分。**

例如，原始 Excel 中商品名称是「芝士猪排大份」，内部商品名称是「爆浆芝士猪排（大份）」。

我们需要保留原始名称，同时记录映射后的内部商品 ID，便于核对和追溯。

#### 2. 初步订单创建规则

| **编号** | **业务规则** | **初步定义** |
| --- | --- | --- |
| ORD-001 | 来源标识 | 每笔订单必须记录来源渠道 |
| ORD-002 | 外部编号 | 每笔外部订单必须记录外部订单编号 |
| ORD-003 | 商品匹配 | 商品必须匹配内部有效商品 |
| ORD-004 | 数量校验 | 商品数量必须大于零 |
| ORD-005 | 客户信息 | 按订单履约要求校验必要信息 |
| ORD-006 | 创建条件 | 关键校验通过后才能创建正式订单 |
| ORD-007 | 失败记录 | 失败订单必须记录具体原因 |

这些是建议的初始规则，还需要业务人员确认。

### 四、确定商品匹配规则

这是订单系统中非常重要的一个业务环节。

例如：

| **外部渠道** | **外部商品名称** | **内部商品** |
| --- | --- | --- |
| 拼多多 | 芝士猪排大份 | 爆浆芝士猪排（大份） |
| 内部系统 | 爆浆芝士猪排-大 | 爆浆芝士猪排（大份） |
| 线下录入 | 芝士猪排大份装 | 爆浆芝士猪排（大份） |

虽然名称不同，但它们可能对应同一个内部 SKU。

#### 1. 推荐商品匹配规则

建议按照以下优先级进行匹配：

#### 商品匹配策略

1. **优先使用渠道商品编码**

外部 SKU 编码与内部映射关系匹配。

2. **其次使用条形码**

通过商品条形码进行匹配。

3. **再使用商品名称与规格**

名称、规格、包装等信息联合匹配。

4. **无法确定时人工匹配**

由运营人员选择正确的内部商品。

这里要特别注意：

不能只根据商品名称自动匹配。

例如：

- 芝士猪排大份。
- 芝士猪排小份。

名称相似，但商品规格不同，错误匹配可能造成库存和金额错误。

#### 2. 商品匹配规则表

| **编号** | **规则** | **处理方式** |
| --- | --- | --- |
| SKU-001 | 渠道 SKU 已建立映射 | 自动匹配 |
| SKU-002 | 条形码唯一匹配 | 自动匹配 |
| SKU-003 | 仅名称相似 | 不直接自动匹配 |
| SKU-004 | 找不到对应商品 | 进入待匹配队列 |
| SKU-005 | 一个外部商品对应多个内部 SKU | 人工确认 |
| SKU-006 | 商品已经停用 | 阻止正常创建并提示处理 |

##### 一个需要特别确认的问题

同一个外部商品可能存在不同规格、组合装、赠品。

例如，一笔订单包含：

- 芝士猪排 2 份。
- 赠品酱料 1 份。

那么系统应该支持一笔订单对应多个订单商品明细，而不是简单地把订单与一个商品关联。

这会影响后续数据库 ER 图设计。

### 五、确定重复订单识别规则

重复订单是一个必须重点控制的问题。

假设运营人员今天上传了 100 笔订单。

明天又上传同一个 Excel 文件。

如果系统不做重复检查，就可能创建 100 笔重复订单。

这会造成：

- 重复审核。
- 重复预留库存。
- 重复发货。
- 财务数据错误。

#### 1. 推荐的重复识别规则

建议使用：

唯一性标识 = 订单来源渠道 + 外部订单编号唯一性标识=订单来源渠道+外部订单编号

例如：

| **来源渠道** | **外部订单编号** | **结果** |
| --- | --- | --- |
| 拼多多 | PDD001 | 首次创建 |
| 拼多多 | PDD001 | 重复订单 |
| 内部系统 | PDD001 | 不同来源，不能仅因编号相同而判重 |
| 拼多多 | PDD002 | 新订单 |

实际项目中还要确认外部订单编号的唯一范围，有些平台的子订单、拆单和合单可能需要更细的业务标识。

#### 2. 重复订单处理策略

| **场景** | **建议处理方式** |
| --- | --- |
| 首次导入 | 正常创建 |
| 同一文件重复上传 | 跳过已处理订单 |
| 不同文件包含同一订单 | 不重复创建 |
| 同一订单信息发生变化 | 进入更新或人工核对流程 |
| 同一订单已经发货 | 不允许普通导入覆盖关键状态 |
| 来源订单编号缺失 | 进入异常队列，不直接创建正式订单 |

这里有一个非常重要的设计：

**重复订单不一定意味着数据完全相同。**

例如，同一笔平台订单第一次导入时状态为待发货，第二次导入时已经变成已发货。

此时应该识别为同一笔订单的状态更新，而不是简单地把第二次数据丢弃。

所以需要区分：

- 重复创建。
- 订单信息更新。
- 订单状态同步。
- 人工修正。

这四种行为必须分别定义规则。

### 六、确定订单信息校验规则

现在我们把订单创建之前的校验分成三类。

#### 1. 必须通过的校验

阻断型校验

这些问题不能直接进入正常订单处理流程。

| **校验项** | **规则** |
| --- | --- |
| 订单编号 | 不允许为空 |
| 订单来源 | 必须能够识别 |
| 商品信息 | 必须匹配有效商品 |
| 商品数量 | 必须大于零 |
| 商品规格 | 必须明确 |
| 重复订单 | 不允许重复创建 |

#### 2. 需要人工确认的校验

人工处理型

| **校验项** | **异常情况** | **处理方式** |
| --- | --- | --- |
| 收货人 | 姓名缺失 | 人工补充 |
| 联系电话 | 格式异常 | 人工核对 |
| 收货地址 | 地址不完整 | 人工修正 |
| 商品匹配 | 无法匹配 | 人工选择 |
| 金额 | 与计算结果不一致 | 人工核对 |

#### 3. 提示型校验

非阻断型

例如：

- 订单备注为空。
- 客户留言较长。
- 商品名称与内部商品名称存在差异，但 SKU 已经可靠匹配。
- 订单存在特殊优惠信息。

这些情况不一定需要阻止订单创建。

#### 4. 校验处理流程

#### 订单信息校验决策

**接收订单数据**

**执行校验规则**

**阻断型**

拒绝创建

**人工型**

待人工处理

**提示型**

记录警告

**所有必要条件通过后创建正式订单**

注意：人工处理型订单可以进入导入批次的待处理记录，但不应该在商品和关键履约信息尚未确认时，直接进入正常库存预留和发货流程。
